# Troubleshooting the Microsoft Entra SaaS source

Find the AADSTS code / HTTP status in the peek, test or aggregation error, then:

| Symptom | Cause | Fix |
|---|---|---|
| `AADSTS7000215: Invalid client secret provided` | The secret's **ID** was entered instead of its **Value**, or a different app's secret | Create a new secret (`entra-setup.sh --rotate-secret --apply`, or `az ad app credential reset --id <appId> --append --display-name "SailPoint ISC" --query password -o tsv > file`) and `configure` again. The Value is only shown once. |
| `AADSTS7000222: client secret keys are expired` | Secret expired | Same as above; consider a calendar reminder at `clientSecretExpires` from `sailpoint-entra-setup.json`. |
| `AADSTS700016: Application … was not found in the directory` | Wrong tenant/Domain Name for that client id, or the app was just created | Check Domain Name is the tenant where the app lives (`az ad app show --id <appId>` while logged into that tenant); right after creation, wait 2–5 min. |
| `AADSTS90002: Tenant … not found` | Typo in Domain Name, or a custom domain that isn't verified | Use the initial `<name>.onmicrosoft.com` domain (shown by `entra-setup.sh` preflight). |
| `AADSTS53003` / `AADSTS50158` / "blocked by Conditional Access" | A Conditional Access policy for workload identities blocks SailPoint's IPs | Exclude the SailPoint service principal or allow SailPoint's egress IPs (from SailPoint support / docs for your region). |
| `403 Authorization_RequestDenied` / `Insufficient privileges to complete the operation` | The Graph permission for that operation isn't **granted** (requested but not consented, or not in the profile) | Rerun `entra-setup.sh --app-id <appId>` with the needed `--profiles` in dry-run: it shows which grants are missing and keeps the app's other permissions. Assigning Global Administrator to the app does **not** replace Graph permissions. Writes on users with admin roles need Privileged Authentication Administrator (`--manage-admin-users`). |
| 403 on aggregation mentioning risk attributes | No permission to read risky users | Grant `IdentityRiskyUser.Read.All` (P2), or remove `riskLevel`, `riskState`, `riskDetail`, `riskLastUpdatedDateTime` from the account schema. |
| SaaS source 403 while a VA-based Azure AD source on the same app works | Different call paths; usually a missing permission, sometimes Conditional Access by IP | Compare granted permissions to the profile list; check CA sign-in logs for the service principal (Entra → Sign-in logs → Service principal sign-ins). |
| Test: `[cam-router]: Test connection failed: Provided source configuration already exists` (sometimes with `[Microsoft-Entra]: 401 Unauthorized`) | Known connector issue | Source → CIEM Settings: enable CIEM, save, disable, save; test again. `verify` stops here; once fixed, rerun `verify` (peek succeeding means the credentials themselves are fine). |
| `peek`/test NullPointerException, no `spConnectorInstanceId` on the source | Source created without `spConnectorSpecId`/`idnProxyType` | Can't be patched in. Delete the source and `create` again (after `discover`). |
| `no schema provided for account list` | Source lacks `spConnectorSupportsCustomSchemas: true` | PATCH it in (`add /connectorAttributes/spConnectorSupportsCustomSchemas true`); the connector can keep old config for a few minutes — retry once. |
| Exchange: `AADSTS70011 invalid scope` / EXO cmdlets fail | Certificate doesn't match the app, Exchange.ManageAsApp not granted, or no Exchange Administrator role | Rerun `entra-setup.sh --profiles exchange --exchange-cert` in dry-run to see what's missing; re-upload the pfx in configure. |
| `DeltaLink older than 30 days is not supported` | Delta token expired | Run a full aggregation (`aggregate`, which disables optimization). |
| `400` on a Graph filter using `dirSyncEnabled` | Old filter attribute | Use `onPremisesSyncEnabled` in the user filter. |
| Entitlement aggregation `ERROR` on `Object Type applicationRole … 403 Authorization_RequestDenied` (accounts aggregate fine) | App lacks `Application.Read.All` | It's in the `readonly` profile now; rerun `entra-setup.sh --app-id <appId>` (dry-run, then `--apply`), wait a few minutes, aggregate again. |
| Peek returns 0 accounts (groups still peek fine), account aggregation adds nothing new | Delta Aggregation is on: the connector returns only changes since the last run (seen live) | Expected in delta mode. `verify` / `aggregate --full` switch delta off for the call and back on. |
| Service principals switched on but none aggregated as accounts | The account schema lacks the `spn_*` attributes (the UI adds them, the API doesn't), and/or a delta run skipped them | `isc-source.sh schema-spn --apply`, then `aggregate --only account --full --apply`. |
| `aggregate` skips datasets: "no dataset has aggregation enabled" | None of the source's datasets is switched on — normal for a directory-only onboarding | `isc-source.sh datasets --source …` lists them. azure:foundry ← `enableAIFoundryAgent` (`configure --profiles ai-agents` + Azure RBAC), microsoft:copilot ← `enableCopilotAIAgent`, microsoft:agent365 ← `enableMicrosoftAgent365` (both need manual setup first). |
| `aggregate-agents` → 404 `The aggregate-agents endpoint is unavailable` | The public dataset-aggregation API isn't exposed on this tenant, although dataset aggregation itself works from the UI (seen live) | Not a path or version problem — don't fall back to another API version. Run it in the UI (source → Dataset Management → Datasets → dataset → Dataset Aggregations), or ask SailPoint to enable the API. |
| Dataset aggregation error `Microsoft Agent 365 aggregation requires a refresh token when Connection Settings uses Client Credentials. Please add the "agent365RefreshToken" value` | `enableMicrosoftAgent365` is on, but Agent 365's catalog API is delegated-only | Turn the toggle off unless Agent 365 is needed. To use it: delegated CopilotPackages.ReadWrite.All + offline_access + User.Read with admin consent, an Agent 365 licence, and a user sign-in to mint the refresh token for `agent365RefreshToken` (tied to that user; expires if unused). |
| Dataset shows `aggregationEnabled: false` after it aggregated fine | That flag is the dataset's *schedule* ("Enable Schedule"), not whether it can run (seen live) | Nothing to fix; `isc-source.sh dataset-schedule --on` (or Enable Schedule in the UI) if it should run periodically. |
| `aggregate-agents` → 400 / 403 | Dataset id not on this source, or the PAT owner lacks the `idn:mis-agents:aggregate` right (Agentic Fabric licence / admin level) | Use ids from `datasets`; check the tenant has Machine Identity Governance / Agentic Fabric and the PAT owner is ORG_ADMIN. |
| `load-accounts` → 400/415 | Wrong content type for the v2026 endpoint | It takes `multipart/form-data` (`-F disableOptimization=true`), not JSON; the script does this. |
| Aggregation task ends `WARNING` | Some objects failed (often one permission missing for one schema, e.g. PIM or Teams) | Read `.messages` (printed by the script, or `GET /v2026/task-status/{id}`); grant the profile for that feature or turn its toggle off. |
| `entra-setup.sh` stops at consent with Authorization_RequestDenied | Signed-in user lacks Global Administrator / Privileged Role Administrator (or it's PIM-eligible, not active) | Activate the role or have such an admin run the `--apply`; the dry-run/plan-only output can be handed over as-is. |
| `admin-consent` / grants fail right after creating the app | Service principal not yet replicated | The script retries for ~1 min; rerun if it still fails — it's idempotent. |
| `The '<api>' service principal isn't in this tenant` | Exchange Online (or another API) not provisioned in the tenant | For Exchange, the tenant needs an Exchange Online licence; otherwise drop that profile. |
| Foundry agents not discovered | RBAC missing on that subscription, or toggle off | `--foundry-subscriptions` for each subscription; turn on "Enable Azure AI Foundry Agents" on the source. |

Retries for transient Graph errors (429/5xx) are configurable on the source ("Retry Configurations" in the
SailPoint docs). For anything else, `isc-source.sh show` (secrets redacted) and the aggregation task messages
(`GET /v2026/task-status/{id}`) usually name the failing call.
